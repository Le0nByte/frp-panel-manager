# Master Deployment

We recommend deploying the Master via Docker! Direct installation on the host is not recommended.

You have three deployment options—choose one.

After deployment, there is no default user. The first registered user becomes the administrator. For security, multi-user registration is disabled by default.

By default, the program stores data in its working directory. To change this, see the configuration reference.

**Important:** If you want to deploy the Master and have it also act as a Server, remember to configure the `default` server in the Web UI after starting the Master.

## Prerequisites

Open the following ports on your server:

- **WEB UI port**: TCP 9100 (loopback only)
- **RPC port**: TCP 9101
- **frps API port**: any free port (example uses TCP/UDP 7000)  
- **frps service ports**: any port range (example uses TCP/UDP 26999–27050)  

API port 9100 is loopback-only and must not be exposed publicly; the reverse proxy forwards public HTTPS to `127.0.0.1:9100`.
- Agent TLS gRPC port 9101 must remain publicly reachable and cannot be disabled or multiplexed through the API proxy.
- Do not multiplex the API, h2c, and Agent gRPC surfaces in production.

To secure communication (via reverse proxy), refer to the diagram below to set the environment variables `CLIENT_RPC_URL` and `CLIENT_API_URL`.

**Note⚠️:** First deploy successfully using the regular method! Then adjust these two variables!!!!

Orange indicates insecure, green indicates secure. You need to ensure both environment variables are set for proper operation.

![](../public/images/frp-panel-platform-connection-env.svg)

> To test if a port (e.g. 8080) is open, run on the server:  
> ```shell
> python3 -m http.server 8080
> ```  
> Then from another host:  
> ```shell
> curl http://SERVER_IP:8080 -I
> ```

## Deploying on Linux

### Option 1: Docker Compose

> Set `MASTER_API_HOST` to the public IP or DNS name that Agents actually connect to. It is included in the TLS certificate SAN. The Master API still listens only on `127.0.0.1:9100`; public management access is provided by the HTTPS reverse proxy.

Install Docker and Docker Compose, then create `docker-compose.yaml`:

```yaml
services:
  frpp-master:
    image: vaalacat/frp-panel:latest
    network_mode: host
    environment:
      APP_GLOBAL_SECRET: your_secret # Enter some random characters, do not leak
      MASTER_RPC_HOST: 1.2.3.4 # Server's external IP or domain
      MASTER_RPC_PORT: 9101 # public Agent TLS gRPC listening port
      MASTER_API_HOST: 1.2.3.4 # Server's external IP or domain
      MASTER_API_PORT: 9100 # loopback API/WebUI port; public HTTPS is provided by the reverse proxy
      # Set CLIENT_RPC_URL and CLIENT_API_URL according to actual situation, set as URLs accessible from outside to master
      # Client connects to master RPC URL, if using reverse proxy, set to the URL accessible through reverse proxy (e.g. grpc://PUBLIC_IP_OR_DNS:9101)
      CLIENT_RPC_URL: grpc://1.2.3.4:9101
      # Client connects to master API/WebUI URL, if using reverse proxy, set to the URL accessible through reverse proxy (e.g. https://example.com:443)
      CLIENT_API_URL: https://1.2.3.4:9443
    volumes:
      - ./data:/data # Data storage location
    restart: unless-stopped
    command: master
```

### Option 2: Docker CLI

Install Docker. We recommend `host` network mode:

```bash
# Recommended
# Keep MASTER_RPC_HOST at 0.0.0.0 for listening; set MASTER_API_HOST to the public IP or DNS used by Agents
# APP_GLOBAL_SECRET should not be leaked, client and server secrets are generated by Master
# Set CLIENT_RPC_URL and CLIENT_API_URL according to actual situation
# If using reverse proxy, set to the URL accessible through reverse proxy, i.e. how to access master from outside
# e.g. if port 443 proxies example.com to the loopback API port 9100
# CLIENT_RPC_URL=grpc://PUBLIC_IP_OR_DNS:9101
# CLIENT_API_URL=https://example.com:443
docker run -d \
  --network=host \
  --restart=unless-stopped \
  -v /opt/frp-panel:/data \
  -e APP_GLOBAL_SECRET=your_secret \
  -e MASTER_RPC_HOST=0.0.0.0 \
  -e MASTER_API_HOST=PUBLIC_IP_OR_DNS \
  -e CLIENT_RPC_URL=grpc://PUBLIC_IP_OR_DNS:9101 \
  -e CLIENT_API_URL=https://PUBLIC_IP_OR_DNS:9443 \
  vaalacat/frp-panel
```

> This fork does not support deploying the Master through Docker bridge port mappings. The API is fixed to the container loopback address, which docker-proxy cannot reach. Use the `--network=host` method above.

### Option 3: Host HTTPS Reverse Proxy (Recommended)

The Master API is fixed to `127.0.0.1:9100`. The reverse proxy must run in the host network namespace (as a host service, or explicitly with `network_mode: host` on Linux). A bridge-network container cannot reach the Master's container loopback address.

Requirements:

1. Run the Master with `network_mode: host` and set `MASTER_API_HOST=PUBLIC_IP_OR_DNS`.
2. Run Nginx, Caddy, or Traefik in the host network namespace. Listen on public HTTPS `9443` (or `443`) and proxy to `http://127.0.0.1:9100`.
3. Keep Agent TLS gRPC `9101` publicly reachable; do not multiplex it through the API reverse proxy.
4. Agents use `CLIENT_API_URL=https://PUBLIC_IP_OR_DNS:9443` and `CLIENT_RPC_URL=grpc://PUBLIC_IP_OR_DNS:9101`.

Use [`ops-runbook.md`](../ops-runbook.md) as the production source of truth for certificates, verification, and rollback.

## Deploying on Windows

### Direct Execution

In the same folder as the downloaded executable, create a `.env` file (note: no file extension), then enter the following content, save, and run the corresponding command:

```
APP_GLOBAL_SECRET=your_secret
DB_DSN=data.db
MASTER_API_HOST=IP
CLIENT_RPC_URL=grpc://IP:9101
CLIENT_API_URL=https://IP:9443
```

- master: `frp-panel-amd64.exe master`
